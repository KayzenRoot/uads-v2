# M03 S05.2 — Host Subject Identity & Passive Evidence Contract

Status: FROZEN FOR EXECUTION
Work Order: UADS2-WO-007
Issue: #30

## 1. HostCapabilitySubject

Recommended shape:

```text
schema: uads.host-capability-subject
schemaVersion: 1.0.0
adapterId
adapterContractVersion
adapterContractDigest
rootBindingVersion
rootIdentityDigest
targetRootDigest
rootKind
sourceClass
runtimeVersion
subjectDigest
```

No absolute paths.

### Subject digest

Compute SHA-256 over a locale-independent canonical representation excluding `subjectDigest`.

Include a fixed domain/schema/version.

Do not include timestamps.

Same semantic host/root/contract/runtime facts => same subjectDigest.

## 2. Adapter contract digest

Digest the normalized exact adapter definition plus:
- adapter contract version;
- relevant root-binding version/domain when it affects identity semantics.

The capability declaration map is part of the digest.

The builtin registry's fixed-contract validation remains authoritative.

## 3. Passive state digest

Build a privacy-safe deterministic digest representing the current non-active observation needed to decide whether a passive proof remains current.

Bind at least:
- detection status;
- sorted semantic reason codes;
- rootIdentityDigest;
- targetRootDigest;
- runtimeVersion;
- adapterContractDigest.

Do not include detectedAt.

Use this digest as the PCCR `configurationDigest` for the passive bridge.

That makes root-presence/status drift invalidate old proof without changing PCCR schema.

## 4. Passive proof constants

Recommended:
- probeId: `passive.adapter-contract.v1`
- fixed probeDefinitionDigest for this exact passive algorithm
- fixed policyDigest for this exact mapping policy

Changing the algorithm/policy must change the corresponding digest.

## 5. Passive mapping

For each current legacy capability:

### BLOCKED target
```
state = BLOCKED
evidenceClass = E1
negativeProofKind = null
```

### UNAVAILABLE / UNPROVEN target
```
state = UNKNOWN
evidenceClass = E1
negativeProofKind = null
```

### SUPPORTED target + declaration true
```
state = UNKNOWN
evidenceClass = E1
negativeProofKind = null
reason includes ADAPTER_DECLARATION_TRUE_NOT_PROOF
```

### SUPPORTED target + declaration unknown
```
state = UNKNOWN
evidenceClass = E1
negativeProofKind = null
```

### SUPPORTED target + fixed declaration false
```
state = UNSUPPORTED
evidenceClass = E2
negativeProofKind = adapter-contract-impossible
```

There is no passive SUPPORTED path.

## 6. Evidence digest

Per capability, hash only privacy-safe normalized evidence:
- subjectDigest;
- adapterContractDigest;
- capabilityId;
- declared value;
- detection status;
- semantic reason codes;
- passive state digest.

No path/raw file content.

## 7. Current PCCR basis

Build a `HostCapabilityCurrentBasis` per capability using:
- subjectDigest;
- adapterId;
- runtimeVersion;
- adapterContractDigest;
- passive probeDefinitionDigest;
- passive policyDigest;
- passive state digest as configurationDigest.

All ten capabilities may share the same current basis except evidenceDigest is proof-specific and not part of the current basis.

## 8. Bridge output

Recommended result:

```text
PassiveHostCapabilityBridgeResult {
  subject
  detection {
    adapterId
    status
    version
    reasonCodes
  }
  proofs: Record<ModelCapability, HostCapabilityProofRecord>
  currentBasis: Record<ModelCapability, HostCapabilityCurrentBasis>
  projectedRuntime: RuntimeCapabilitySnapshot
  persistence?: per-capability telemetry status
}
```

Do not return raw paths.

## 9. Persistence

Persist PCCR through existing `persistHostCapabilityProof()`.

When telemetry context is provided:
- use existing `evidence.lifecycle`;
- source remains `m03.host-capability`;
- telemetry failure cannot change proof truth.

## 10. Legacy base snapshot

Do not trust `runtimeSnapshotFromHostDetection()` capability values as PCCR truth.

Construct a conservative legacy metadata snapshot with all capabilities UNKNOWN, using only safe identity metadata:
- runtimeId = `host-<adapterId>`;
- adapterId;
- adapterVersion;
- runtimeVersion nullable.

Then apply PCCR projection.

## 11. Drift behavior

Example:

1. generic adapter target exists;
2. passive bridge proves `subagents=false` through E2 contract-impossible;
3. target root is removed;
4. recompute passive subject/current basis;
5. prior proof MUST no longer project false.

Result: UNKNOWN/STALE, not FALSE.

## 12. Compatibility

Do not change the ten-capability legacy schema in this slice.

Do not migrate host-dispatch automatically in WO-007 unless objective tests prove a minimal integration is required. A later integration/hardening slice can switch consumers to the passive proof-aware bridge.

## 13. Security

No imports/use of:
- node:child_process;
- HTTP/network client;
- shell command parser.

Filesystem reads used by existing host detection/root resolution are allowed; no host-root mutation is allowed by this bridge.

## 14. STOP

Do not implement active probes or future capability IDs.
