# M03 S06.2 — Proof-Aware Consumer Boundary

Status: IMPLEMENTED CANDIDATE — WO-012 HEDS PENDING

## Canonical production consumer API
Future HARD consumers M01, M04, M06 and M23 must consume M03 capability truth through:

`readHostCapabilityProjection()` from `src/adapters/host-capability-consumer.ts`.

They must not consume adapter-declared capability values or `runtimeSnapshotFromHostDetection()` as enabling truth.

## Contract
The API returns:
- conservative `RuntimeCapabilitySnapshot` compatibility projection;
- privacy-safe `subjectDigest`;
- `adapterContractDigest`;
- bounded detection summary.

Only proof-aware projection may produce enabled TRUE. Current passive declaration TRUE remains UNKNOWN. Current static negative proof may produce FALSE only under NPC semantics.

## Persistence boundary
The consumer API is read-oriented and non-persisting by default. It does not create PCCR proof records and does not create project-local state.

## Evolution rule
The current internal provider is the passive PCCR bridge. Future active/stored proof resolution may replace or augment that provider behind this API without changing consumer-facing truth semantics. This prevents M01/M04/M06/M23 from coupling to probe, storage, or passive-bridge internals.

## Legacy compatibility
`runtimeSnapshotFromHostDetection()` may remain for explicit legacy/eval compatibility coverage, but it is not an authorized production capability-truth boundary.

## Freeze implication
M03 S07 may freeze the module only after this boundary and remaining frozen obligations are reviewed and no production consumer bypass is found.
