# M30 S01.5 — Proprietary Invention Radar

Status: IMPLEMENTED CANDIDATE — HEDS PENDING
Parent: M30 Production Observability & Real-Time Operations
Issue: #53

## Purpose
Convert the market gaps frozen in S01 into a bounded set of UADS-native mechanisms for truthful observability and governed control. This stage selects concepts for architecture work only. It does not claim implementation.

## Product direction
The operator surface is a Living Operations Organism: a real-time control plane that exposes all practical system state, causality, evidence, resource pressure, costs, failures, queues, releases, security posture and governed actions while remaining truthful under partial failure.

## Candidate dispositions

### P1 — Operational Truth Confidence Layer (OTCL)
Disposition: PROMOTE
Problem: dashboards commonly collapse source age, lineage and availability into visual labels with weak semantics.
Decision: every operator-visible datum must resolve source identity, observed timestamp, evaluation timestamp, freshness lease/budget, derivation lineage and state CURRENT, STALE, DEGRADED or UNAVAILABLE. Confidence may describe evidence quality, never invent probability.
Why proprietary value exists: OTCL unifies truthfulness rules across UADS domain sources, host capability proof, telemetry and derived projections while preserving source authority.
Proof obligations: deterministic state transitions; stale-clock tests; source-loss tests; lineage preservation; zero false CURRENT under missing/expired evidence; bounded evaluation overhead.

### P2 — Telemetry Continuity Ledger (TCL)
Disposition: PROMOTE
Problem: event streams can reconnect, drop, compact or arrive out of order while dashboards continue looking healthy.
Decision: maintain bounded continuity evidence using source/stream identity, sequence or equivalent continuity markers, observed gaps, replay range, drop/reject counters and UNKNOWN continuity when proof is insufficient.
Why proprietary value exists: UADS needs continuity truth across local journal, SSE and future distributed adapters without assuming a particular broker.
Proof obligations: deterministic gap detection; reconnect/replay tests; duplicate/out-of-order handling; compaction disclosure; no false COMPLETE continuity claim.

### P3 — Adaptive Observability Budget Controller (AOBC)
Disposition: PROMOTE
Problem: observability can consume enough CPU/latency/storage to distort the workload it measures. Issue #39 proves this risk is real in UADS.
Decision: enforce explicit observability budgets and reduce non-essential detail before budget breach. Priority order must preserve correctness/critical evidence over diagnostic richness. Adaptation is asynchronous or amortized, not a heavy per-event control loop.
Why proprietary value exists: integrates UADS workload classes, evidence criticality, local hardware capability and operational truth instead of using static sampling alone.
Proof obligations: CPU/latency/storage/cardinality ceilings; no loss of mandatory audit/security events; deterministic degradation policy; recovery hysteresis; benchmark against Issue #39 baseline.

### P4 — Cardinality Budget Firewall (CBF)
Disposition: PROMOTE AS AOBC SUBSYSTEM
Problem: high-cardinality attributes can destabilize metrics/storage and create cost explosions.
Decision: consolidate CBF into AOBC rather than create an independent top-level subsystem. Provide per-domain/attribute budgets, bounded labels, deterministic overflow aggregation/drop policy and explicit dropped-series evidence.
Proof obligations: adversarial cardinality tests; bounded memory/storage; secret/raw-prompt rejection; deterministic overflow behavior.

### P5 — Truth/Projection Separation Contract (TPSC)
Disposition: PROMOTE
Problem: derived metrics, summaries and dashboard views can accidentally become treated as authoritative domain state.
Decision: define a universal contract distinguishing SOURCE, DERIVED and PRESENTATION states. Derived outputs retain lineage and cannot mutate or supersede authoritative source state without an owning-module command.
Why proprietary value exists: this is a cross-module governance primitive joining observability, Work Orders, capabilities, costs and control-plane actions.
Proof obligations: lineage tests; prohibited write-through tests; derived-state invalidation; no authority escalation through aggregation.

### P6 — Local-to-Distributed Continuity Bridge (LDCB)
Disposition: EXPERIMENT
Problem: local-first storage must eventually scale without semantic migration or identity breakage.
Decision: preserve event identity/truth/continuity contracts while allowing optional durable queue, object-store or remote exporter adapters only when M27 evidence justifies scale-out.
Reason not yet PROMOTE: distributed transport/storage selection belongs after architecture and load evidence.
Proof obligations: identity preservation across adapter boundary; replay equivalence; partial outage; backpressure; duplicate delivery; local fallback.

### P7 — Privacy-Safe Correlation Fabric (PSCF)
Disposition: PROMOTE
Problem: causal debugging needs correlation across Work Orders, requests, agents, releases and modules, but naïve correlation leaks prompts, paths or secrets.
Decision: use stable bounded opaque correlation identifiers and explicit permitted joins. Raw prompts, secrets and sensitive paths are not correlation keys.
Proof obligations: cross-module join coverage; collision/rotation strategy; privacy red-team; bounded cardinality; no raw sensitive-data dependency.

### P8 — Living Operations Control Plane (LOCP)
Disposition: PROMOTE
Problem: visibility without governed action forces operators to leave the operational surface and breaks context/evidence continuity.
Decision: M30 composes module-provided state and governed command capabilities into one control graph. M30 never owns business/domain state. Every action declares owner, authorization requirement, risk class, expected effect, audit receipt, idempotency/retry semantics where applicable, blast radius and recovery/rollback path.
Proof obligations: owner-bound command routing; unauthorized action denial; audit completeness; stale-state action rejection; partial-failure UI; deterministic terminal command state.

### P9 — Causal Operations Graph (COG)
Disposition: EXPERIMENT
Problem: raw timelines force humans to manually correlate symptom, resource pressure, deployment and upstream events.
Decision: build an evidence graph from deterministic relationships first; probabilistic/root-cause inference may be added later but must be visibly labeled as hypothesis with supporting/contradicting evidence.
Reason not yet PROMOTE: automatic causal inference can create dangerous false certainty.
Proof obligations: deterministic edge provenance; cycle/bounds controls; hypothesis labeling; false-cause benchmark; operator drill-down to raw evidence.

### P10 — Adaptive Attention Engine (AAE)
Disposition: EXPERIMENT
Problem: maximal visibility can become maximal noise.
Decision: rank and summarize attention using objective severity, impact, freshness, uncertainty and operator scope while preserving full drill-down. High-severity unresolved or uncertain evidence cannot be suppressed.
Reason not yet PROMOTE: prioritization quality requires operator-usefulness evaluation and anti-hiding proof.
Proof obligations: no critical-hidden invariant; dedup/noise-reduction benchmark; explanation of ranking factors; stable behavior under event storms.

## Consolidated S02 shortlist
Top-level primitives promoted to S02 architecture:
1. OTCL — operational truth/freshness semantics.
2. TCL — continuity/gap semantics.
3. AOBC — adaptive observability budget governance, including CBF.
4. TPSC — source/derived/presentation authority separation.
5. PSCF — privacy-safe correlation.
6. LOCP — living governed control plane.

Experimental architecture hooks, not mandatory implementation:
- LDCB — local-to-distributed continuity bridge.
- COG — causal operations graph.
- AAE — adaptive attention engine.

Rejected as separate top-level primitive:
- CBF as a standalone subsystem. Its value is retained inside AOBC.

## Cross-cutting invariants
- A datum cannot be CURRENT without valid freshness evidence.
- Silence is not health when continuity evidence is missing.
- Derived/projected state cannot silently become source truth.
- Observability must obey a resource budget and expose its own degradation.
- Correlation cannot depend on secrets/raw prompts/sensitive paths.
- Control-plane actions must route to the authoritative owning module.
- Every governed action emits auditable evidence.
- Partial failure must preserve truthful partial visibility.
- Real-time is an evidence property, not a refresh-rate claim.

## Enterprise pillar impact
- M27 Scale/Load: AOBC + LDCB hooks; quantitative targets deferred to benchmark design.
- M28 Resilience/Recovery: TCL + LOCP recovery semantics; partial-failure truth mandatory.
- M29 Operational Security/Supply Chain: PSCF privacy boundaries; LOCP authorization/audit; no mandatory external stack.
- M30 Production Observability: owns all six promoted primitives and three experimental hooks.
- M31 Release Engineering/Safe Ops: LOCP must expose governed release/rollback controls only through owning release modules; OTCL/TCL evidence feeds release health.

## S02 handoff
S02 must place the six promoted primitives into bounded components/contracts, define state machines and APIs, and reserve optional seams for LDCB/COG/AAE. No implementation is authorized merely by this promotion.
